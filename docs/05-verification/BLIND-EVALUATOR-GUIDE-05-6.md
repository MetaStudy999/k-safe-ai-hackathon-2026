# 05-6 별도 평가자용 작성 안내서와 빈 양식

현재 상태: **EVALUATOR_READY / DATA_PENDING**. 아직 독립 평가 자료가 없으며 평가 결과도 없습니다.

이 문서와 [빈 JSON 양식](blind-evaluation-empty.json)만 별도 평가자에게 전달하세요. 평가자는 개발 담당자와 다른 사람이어야 하며, 탐지 코드·기존 합성 자료·정답·기준선 결과를 보지 않고 작성합니다. 이 안내서는 탐지 규칙이나 완성된 예문을 제공하지 않습니다.

## 1단계 — 독립 작성 여부 확인

1. 개발에 참여하지 않았고 탐지 코드와 기존 사례를 보지 않았는지 확인합니다. 이미 보았다면 다른 작성자를 구합니다.
2. 실제 피해자의 메시지나 인터넷 사례를 복사하지 않고 새로운 가상 상황을 직접 만듭니다. 기존 자료를 바꿔 쓰거나 규칙의 키워드를 맞추는 방식은 금지합니다.
3. 본인이 의도한 상황을 기준으로 라벨을 붙입니다. 프로그램의 답을 보고 라벨을 바꾸지 않습니다.

## 2단계 — 파일 준비

최종 파일 위치는 프로젝트 밖 `/home/ubuntu/k-safe-eval-external.json`입니다. 다른 계정에서는 `$HOME/k-safe-eval-external.json`을 사용하세요. 이 파일을 Git에 등록하지 않습니다.

빈 양식의 내용은 `[]`뿐입니다. 사례·정답·평가 결과가 들어 있지 않습니다. **빈 양식은 유효한 JSON이지만 사례 수가 0건이므로 검증에 실패하는 것이 정상입니다.** 작성 전에는 최종 경로에 파일을 만들 필요가 없습니다.

작성자가 Ubuntu 터미널을 사용한다면 다음 명령으로 별도 작업 파일부터 만들 수 있습니다. `cp -i`가 덮어쓸지 물으면 기존 파일을 유지하세요.

```bash
cd /home/ubuntu/codyssey/k-safe-ai-hackathon-2026
cp -i docs/05-verification/blind-evaluation-empty.json "$HOME/k-safe-eval-draft.json"
```

텍스트 편집기에서 작업 파일을 열고 대괄호 안에 사례 객체를 작성합니다. 객체는 `{}`로 감싸고 필드와 객체 사이는 쉼표로 구분합니다. 필드명과 문자열 값에는 큰따옴표(`"`)를 사용하며 마지막 항목 뒤에는 쉼표를 붙이지 않습니다. UTF-8로 저장하고 JSON 안에 주석을 넣지 않습니다.

## 3단계 — 사례마다 네 필드 작성

| 필드 | 작성 방법 |
|---|---|
| `id` | 서로 다른 사례 식별자. 대문자·숫자·밑줄(`_`)·하이픈(`-`)만 사용해 2~32자. 예: `EX001`. 개인정보를 쓰지 않습니다. |
| `expected` | `scam`, `benign`, `borderline` 중 하나. 아래 라벨 기준을 따릅니다. |
| `category` | 작성자가 정한 상황의 짧은 이름. 앞뒤 공백을 뺀 내용이 최소 2자, 전체 80자 이하. |
| `message` | 작성자가 새로 만든 가상 메시지. 공백만 쓰지 않으며 전체 1~2,000자. |

네 필드는 모두 문자열이며 필수입니다. 다른 필드(예측값·점수·검토 메모 등)는 넣지 않습니다. 라벨 검토 이유와 작성 이력은 별도 문서에 보관합니다. 위 표는 필드 설명이며 평가 사례나 정답표가 아닙니다.

| 라벨 | 기준 | 최소 건수 |
|---|---|---:|
| `scam` | 작성자가 금융사기 위험 상황으로 의도한 가상 메시지 | 10 |
| `benign` | 명백히 일반적인 정상 상황으로 의도한 가상 메시지 | 10 |
| `borderline` | 정보가 부족하거나 검토자 간 판단이 달라 확정하기 어려운 메시지 | 4 |

전체 **24~200건**, 파일 크기 **256KiB 이하**로 작성합니다. 경계 사례는 별도로 보고하며 재현율·오경보율 계산에서 제외합니다. 같은 문장을 반복해 건수만 채우지 말고 다양한 상황·표현·길이를 포함하세요.

## 4단계 — 민감정보와 라벨 검토

실제 전화번호·계좌·카드·주민번호·이메일·이름·주소·비밀번호·피해 원문·악성 링크를 넣지 않습니다. 숫자를 지어내도 실존 값과 겹칠 수 있으므로 `[가상연락처]`, `[가상계좌]`, `[가상신분번호]`, `[가상링크]`, `[가상비밀번호]`처럼 글자로 표시하세요. 실제로 접속할 수 있는 URL을 작성할 필요가 없습니다.

검사기는 `id`, `category`, `message`의 전화·신분번호·이메일·긴 숫자(계좌/카드 형태)와 `http://`, `https://`, `www.` 형식을 거부합니다. 점·공백·하이픈으로 구분된 숫자와 전각 문자도 일부 검사합니다. **이 검사는 개인정보 없음이나 독립 작성을 보장하지 않습니다.** 이름·주소·비밀번호, 다른 구분자나 가려진 형태, 프로토콜 없는 도메인 등은 사람이 직접 확인해야 합니다. 검사 오류에는 해당 값 대신 행 번호와 필드명만 표시합니다.

가능하면 두 사람이 라벨을 검토하고, 의견이 일치하지 않는 사례는 이유를 별도 기록한 뒤 `borderline`으로 분류합니다. 이후에도 최소 라벨 건수를 만족하는지 확인합니다.

## 5단계 — 분석 없이 형식 검증

먼저 Node.js 버전이 `v24.22.0`인지 확인합니다. 다음 명령은 **탐지 함수를 호출하지 않으며 점수를 계산하지 않습니다.** 작업 파일에 대해 반복해도 됩니다.

```bash
cd /home/ubuntu/codyssey/k-safe-ai-hackathon-2026
export PATH="$HOME/.nvm/versions/node/v24.22.0/bin:$PATH"
node --version
node --import tsx scripts/evaluate-blind.ts "$HOME/k-safe-eval-draft.json" --validate-only
```

| 출력 | 의미와 다음 행동 |
|---|---|
| `DATA_FILE=NOT_FOUND` | 파일이 없습니다. 출력된 경로와 저장한 위치를 확인합니다. 평가 미실행이며 종료 코드는 1입니다. |
| `DATA_FILE=READ_ERROR` | 파일을 읽지 못했습니다. 파일 경로·권한을 확인합니다. 종료 코드는 1입니다. |
| `DATA_FILE=INVALID`, `VALIDATION=FAIL` | 형식·필드·건수·중복·민감정보 형식 등을 고쳐 다시 검사합니다. 종료 코드는 1입니다. |
| `"validation": "PASS"`, `"evaluation": "NOT_RUN"` | 형식 검증만 통과했습니다. **탐지 품질 PASS가 아닙니다.** 종료 코드는 0입니다. |

검증 성공 시 `data_sha256`도 출력됩니다. SHA-256은 파일의 내용이 바뀌었는지 확인하는 지문입니다. 공백이나 줄바꿈만 바뀌어도 달라집니다.

## 6단계 — 동결·인계 후 최초 평가

1. 검토를 마친 작업 파일을 최종 위치에 보관합니다. 기존 최종 파일이 있으면 덮어쓰지 말고 먼저 버전을 확인하세요.
2. 최종 파일도 `--validate-only`로 다시 검사합니다. 작성자·검토자·작성 시각·독립 작성 확인·라벨 검토 근거는 별도로 기록합니다.
3. 최종 `data_sha256`과 `git rev-parse HEAD` 출력을 기록합니다. 커밋되지 않은 코드 변경이 있다면 코드 사본과 `git diff`도 별도로 보관해 실제 평가할 코드를 식별합니다. 기록을 위한 새 Git 커밋은 필수가 아닙니다.
4. 파일·라벨·탐지 코드를 동결한 후에만 개발 담당자가 아래 평가 명령을 실행합니다. 최초 출력은 그대로 보존하고 실행 후 해시도 대조합니다.

```bash
cd /home/ubuntu/codyssey/k-safe-ai-hackathon-2026
node --import tsx scripts/evaluate-blind.ts "$HOME/k-safe-eval-external.json" --validate-only
# 사람의 검토와 파일/코드 동결이 완료된 후에만 아래 실행
node --import tsx scripts/evaluate-blind.ts "$HOME/k-safe-eval-external.json"
```

데이터가 아직 없으면 마지막 명령을 실행하지 않습니다. 성능 수치·PASS를 만들어 기록하지 않고 **EVALUATOR_READY / DATA_PENDING**으로 남깁니다. 첫 결과를 보고 문장·정답·규칙을 바꾸면 해당 자료는 이후 회귀시험용이며 새 독립 자료로 부르지 않습니다.
