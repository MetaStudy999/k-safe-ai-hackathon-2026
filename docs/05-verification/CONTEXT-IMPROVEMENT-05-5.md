## 1. 개선 내용 (작성, 미검증)

| 개선 방향 | 구현 개요 | 위험·한계 |
|---|---|---|
| 고위험 행동 묶음 | 택배 주소 변경 요구, 수사기관 비밀 채팅 유도, 지원금 개인정보 인증, 거래처 계좌 변경, 원격지원 설치, 외부 결제·인증, 은행 비밀번호 요구, 재배송 비용 결제 | 새 표현·어순·띄어쓰기에 여전히 취약할 수 있음 |
| 교육·설명 문맥 | 보안 강의, 수업, 분석, 문구 디자인 등 설명 목적의 단어와 명시적 행동 요구를 구분 | 고의로 교육을 사칭하는 공격에 대한 우회 가능성 |
| 안전한 불확실성 | 신호 하나만 있으면 `review`, 위험 설명에는 확정 불가 고지 유지 | `no_clear_signal`이 여전히 안전 보증은 아님 |
| 위급 상황 고정 조치 | 이미 송금한 상황에는 신호와 무관하게 112·금융회사 즉시 안내 | 실제 신고·지급정지를 자동 실행하지 않음 |

**코드:** `src/lib/safety.ts`에 8개 상황 조합 규칙과 교육문맥 참고 조건을 작성했다. 이 기능은 **LLM이나 자연어 이해 모델이 아니라 정규식 기반 휴리스틱**이다.
