## 0. 1분 요약

**현재 K-SAFE는 로컬 규칙 기반 MVP로 동작하며, 공개 배포는 아직 금지한다.**

- TypeScript·자동 테스트 **33/33**, Next.js 빌드 **PASS**(기존 사용자 Ubuntu 로그)
- 로컬 HTTP 통합검증 **8/8 PASS**(2026-10-30 사용자 Ubuntu 로그)
- 실제 외부 WAF(Web Application Firewall, 웹 애플리케이션 방화벽) 요청률 제한·429 **미확인**
- 개인정보·민감정보 처리 및 클라우드 호스팅 로그 **미확인**
- 외부 LLM(Large Language Model, 대형언어모델) **미연결**. 실제 대회 AI 필수 조건을 별도로 확인해야 함

## 2. 단계를 구분하여 안전하게 배포하기

1. **지금: 로컬만 운영.** 네트워크에 서비스 공개 금지, 실제 개인정보 입력 금지.
2. **향후 별도 승인 시: 보호 상태의 시험 배포.** 필요하면 외부 접속을 제한한 비공개 프리뷰(Preview)로 먼저 검증. 프로덕션 `RATE_LIMIT_RULE_VERIFIED=false`를 유지하여 분석 API는 503으로 막음. 비공개 설정·요금·프로젝트 권한 확인 후 진행.
3. **WAF 설정 및 실제 응답 검증.** `/api/analyze`와 해당 호스트/프리뷰 URL에 요청률 제한 적용, 의도적으로 소량의 테스트 요청만 보내 허용/차단을 확인. 높은 부하를 발생시키거나 타 사이트에 테스트하지 않음.
4. **호스팅 로그·비밀키·요청 크기 재확인.** 실제 API 요청 본문과 민감정보가 보관되지 않는지, 서버 로그·제3자 관찰도구·배포 환경변수·보안 헤더를 점검.
5. **검증 후 보호 활성화.** WAF가 실제 유효함이 증명될 때만 `RATE_LIMIT_RULE_VERIFIED=true`를 설정. 이 값 자체가 WAF를 만들지는 않음. 규칙을 철회하거나 변경하면 즉시 false로 되돌림.
6. **공식 공고·AI 요건 확인 후 최종 제출.** 현행 규칙 기반 엔진을 'AI 모델 구현 완료'라고 표기하지 않는다.

## 4. 개발환경 작업물

로컬은 `/home/ubuntu/codyssey/k-safe-ai-hackathon-2026`이며 사용자가 보고한 작업물:

```text
 M next-env.d.ts
?? package-lock.json
```

보존하고 `git reset --hard`, `git clean` 등을 사용하지 않는다. `package-lock.json`은 현재 설치 패키지 재현성을 위해 **내용 검증 후 별도 커밋**하도록 하며, 본 문서에서는 복사·수정·등록하지 않는다.
