## 0. 현재 상태와 목표

04-6에서 사용자가 직접 **브라우저 5개 항목 PASS**를 확인했다. 04단계 **규칙 기반 MVP**는 정상 동작하지만, **05단계 보안 및 성능 검증은 별개**다.

이 단계의 목적은 **정확도 과장 방지**, **개인정보 처리 위험**, **API 오남용 위험**, **배포 전 필수 개선점**을 찾아 측정·수정하고 재시험하는 것이다.

### 검증 구분

- **기존 실제 확인:** Node24, npm 설치, TypeScript 검사, 기존 9/9 자동 단위시험, Next.js 빌드, 04-4 HTTP/API 기본 응답, 04-6 사용자 브라우저 5/5.
- **05에서 새로 마련한 자료:** [합성 사례 30개](../../data/synthetic/verification-cases.ts), [평가 실행기](../../scripts/evaluate-synthetic.ts).
- **05 신규 평가 결과:** 실제 실행 전에는 **NOT_RUN**. 결과 확인 후에만 수치 기입한다.
- **LLM(대형언어모델) 설명 기능:** 현재 구현 **없음**. 규칙 기반 코드만 검증 가능.

## 1. 05-1 합성 자료 평가 방법

| 분류 | 건수 | 의미 |
|---|---:|---|
| 위험(Scam) 가상 메시지 | 15 | 선입금·기관 사칭·가족 사칭·택배·결제취소 등 위험 시나리오 |
| 정상(Benign) 가상 메시지 | 10 | 일상 연락·교육용 문장 등 |
| 경계(Borderline) | 5 | 맥락이 불충분한 표현. 정확도 계산에서 제외 |
| **합계** | **30** | 모두 합성 문장, 실제 계좌/URL/피해자 데이터 없음 |

**계산식**

- 위험 재현율(Recall, Sensitivity) = 위험 메시지 중 탐지한 건수 / 위험 메시지 15건
- 미탐지(False Negative, FN) = 위험 메시지인데 '명확한 신호 없음'인 건수
- 오경보율(False Positive Rate, FPR) = 정상 메시지인데 경고한 건수 / 정상 메시지 10건
- 경계 사례는 정답 확정이 어려우므로 별도 출력, 위 정확도 계산에서 제외

**주의:** 합성 예시 30건은 대표 표본이 아니며 **실제 국민 대상 탐지율, 피해예방률, 의료·금융적 신뢰성을 주장할 근거가 아니다.** 특정 패턴에 유리한 데이터일 수 있고 수치는 사례 구성에 민감하다. 실제 자료로 검증할 때는 개인정보법·동의·기관 협력 절차 필요.

### Ubuntu에서 실행 (읽기 중심, 외부 서버 불필요)

~~~bash
cd /home/ubuntu/codyssey/k-safe-ai-hackathon-2026
export PATH="$HOME/.nvm/versions/node/v24.22.0/bin:$PATH"
git pull --ff-only origin main
node --import tsx scripts/evaluate-synthetic.ts
~~~

- 출력은 JSON(제이슨, 구조화 데이터)이며 `false_negative`, `false_positive`, `failed_cases`를 우선 확인한다.
- 평가 실행은 Git 커밋·API 요청·데이터베이스 저장·실제 송금을 하지 않는다.
- **문제가 발견되면 실패/위험을 그대로 기록한다.** 테스트를 통과시키려고 정답을 수정하지 않는다.

## 2. 보안 정적 점검 (현재 코드 근거)

| 위험 ID | 현재 코드 관찰 | 현재 판정 | 배포 전 요구 |
|---|---|---|---|
| SR-01 개인정보 전송 | 브라우저·서버의 정규식 마스킹 존재. 주민등록번호·다양한 계좌 형태 등 처리 범위는 불완전할 수 있음. API 직접 호출로 원문 전송 가능 | **PARTIAL** | 금지 입력·추가 마스킹·거부 정책, 요청/응답/로그 점검 |
| SR-02 비밀키 | 외부 AI 사용 없음, 코드에 실제 비밀키 없음. 호스팅 비밀키 정책은 미점검 | **PARTIAL** | 배포 설정 및 클라이언트 번들 검사 |
| SR-03 인젝션 | 규칙 엔진이 문자 속 지시를 실행하지 않음. LLM 연결이 없어 LLM 보안은 미평가 | **PARTIAL** | 악성 입력·XSS·출력검증 시험 |
| SR-04 URL | 현행 API에서 사용자 URL을 자동 fetch하는 기능은 없음 | **소스 점검 PASS** | 동적 링크·네트워크 호출 시험 |
| SR-05 보관 | DB 저장 기능 없음. 프록시/호스팅/오류 로그·실제 요청 데이터는 미검증 | **PARTIAL** | 서버·호스팅 로그 정책 확인 |
| SR-06 남용·비용 | API에 실효성 있는 서버측 요청률 제한이 **없음** | **FAIL / 배포 차단** | 관리형/API 게이트웨이 기반 요청 제한, 총 예산 한도 |
| SR-07 안전한 행동 | 이미 송금 시 112·금융회사 안내 및 안전 보증 금지 문구 존재 | **일부 PASS** | 예외·모호한 문구·긴급 안내 회귀시험 |
| API 입력 본문 제한 | `request.json()` 호출 후에야 메시지 2,000자를 검사하므로 **원시 HTTP 요청 본문 바이트 상한 미적용** | **FAIL / 배포 차단** | JSON 파싱 전 요청 크기 제한·413 응답, 입출력 타입 검증 |
| LLM 기술성 | 외부 LLM 호출/설명 없음. 현재 화면은 규칙 기반이라고 표시 | **미구현** | 실제 대회 필수 AI 조건 확인 후 안전한 연결 또는 범위 재조정 |

**중요:** 정적 코드 검토는 운영환경의 실제 공격 가능성·방어 효과를 입증하지 않는다. 취약점에 대한 동적 검증은 수행한 뒤 별도 판정한다.

## 3. 05-2 시험 계획 (TC/TS)

| 시험 ID | 대상 | 완료 증거 |
|---|---|---|
| V-01 | 30개 합성 위험·정상·경계 분석 | 실제 JSON 결과·오탐/누락 목록 |
| V-02 | 이메일·전화번호·계좌형 번호·주민번호 모양 입력 | 서버 전달/출력 가림 또는 명시적 차단 |
| V-03 | 잘못된 JSON, 빈 입력, 2,001자, 큰 요청 본문 | HTTP 400/413 등 안전한 거부 |
| V-04 | 프롬프트 인젝션/HTML·스크립트 문자열 | 코드 미실행·출력 안전성·고정 안내 유지 |
| V-05 | API 요청 폭증 및 호출 제한 | 429/관리형 제한 정책 실증, 비용 보호 |
| V-06 | 송금 전·후·앱 설치·모름 | 상황별 안내 및 긴급 연락 우선 |
| V-07 | 네트워크/모델 장애 | 규칙 기반 폴백·명시적 상태·긴급 안내 지속 |
| V-08 | 장애 로그·브라우저 응답·비밀키 누출 | 민감정보 없음 |
| V-09 | 실제 모바일·키보드·화면 확대 | 동작·가독성 |
| V-10 | 배포 URL 및 HTTPS | 06단계 배포 후 검증 |

## 4. 개선 우선순위

1. **P0 배포 차단:** 공개 API 요청 제한·최대 HTTP 본문 크기 검사; 실제 민감정보 입력/로그 최소화 정책을 명확히 하고 동적 시험.
2. **P1 중요:** 탐지 누락 및 오경보 사례 분석, 여러 형태의 개인정보 차단/마스킹.
3. **P1 대회 적합성:** AI 기반 추천·정보보호가 주제이므로 규칙 기반 데모만으로 충분한지 공식 공고 검토; AI 설명 연결 시 입력정보/비용/오류 정책 적용.
4. **P2:** 접근성 확대, 발표용 결과 기록, 배포 신뢰성·장애 대응.

## 6. 용어

- **FNR (False Negative Rate, 미탐지율):** 위험 메시지인데 경고하지 못한 비율
- **FPR (False Positive Rate, 오경보율):** 정상 메시지인데 위험하다고 잘못 경고한 비율
- **P0 (Priority 0, 최우선):** 공개 배포 전 반드시 해결할 문제
- **정적 점검(Static Review):** 코드를 읽고 위험을 파악. 실제 보안 공격 검증은 별개
- **요청 제한(Rate Limiting):** 과도한 API 호출 방지
