## 1. 05-1 합성 자료 평가 방법

| 분류 | 건수 | 의미 |
|---|---:|---|
| 위험(Scam) 가상 메시지 | 15 | 선입금·기관 사칭·가족 사칭·택배·결제취소 등 위험 시나리오 |
| 정상(Benign) 가상 메시지 | 10 | 일상 연락·교육용 문장 등 |
| 경계(Borderline) | 5 | 맥락이 불충분한 표현. 정확도 계산에서 제외 |
| **합계** | **30** | 모두 합성 문장, 실제 계좌/URL/피해자 데이터 없음 |

**계산식**

- 위험 재현율(Recall, Sensitivity) = 위험 메시지 중 탐지한 건수 / 위험 메시지 15건
- 미탐지(False Negative, FN) = 위험 메시지인데 '명확한 신호 없음'인 건수
- 오경보율(False Positive Rate, FPR) = 정상 메시지인데 경고한 건수 / 정상 메시지 10건
- 경계 사례는 정답 확정이 어려우므로 별도 출력, 위 정확도 계산에서 제외

**주의:** 합성 예시 30건은 대표 표본이 아니며 **실제 국민 대상 탐지율, 피해예방률, 의료·금융적 신뢰성을 주장할 근거가 아니다.** 특정 패턴에 유리한 데이터일 수 있고 수치는 사례 구성에 민감하다. 실제 자료로 검증할 때는 개인정보법·동의·기관 협력 절차 필요.

## 4. 개선 우선순위

1. **P0 배포 차단:** 공개 API 요청 제한·최대 HTTP 본문 크기 검사; 실제 민감정보 입력/로그 최소화 정책을 명확히 하고 동적 시험.
2. **P1 중요:** 탐지 누락 및 오경보 사례 분석, 여러 형태의 개인정보 차단/마스킹.
3. **P1 대회 적합성:** AI 기반 추천·정보보호가 주제이므로 규칙 기반 데모만으로 충분한지 공식 공고 검토; AI 설명 연결 시 입력정보/비용/오류 정책 적용.
4. **P2:** 접근성 확대, 발표용 결과 기록, 배포 신뢰성·장애 대응.

## 6. 용어

- **FNR (False Negative Rate, 미탐지율):** 위험 메시지인데 경고하지 못한 비율
- **FPR (False Positive Rate, 오경보율):** 정상 메시지인데 위험하다고 잘못 경고한 비율
- **P0 (Priority 0, 최우선):** 공개 배포 전 반드시 해결할 문제
- **정적 점검(Static Review):** 코드를 읽고 위험을 파악. 실제 보안 공격 검증은 별개
- **요청 제한(Rate Limiting):** 과도한 API 호출 방지
