## 1. 05-1 합성 자료 평가 방법

| 분류 | 건수 | 의미 |
|---|---:|---|
| 위험(Scam) 가상 메시지 | 15 | 선입금·기관 사칭·가족 사칭·택배·결제취소 등 위험 시나리오 |
| 정상(Benign) 가상 메시지 | 10 | 일상 연락·교육용 문장 등 |
| 경계(Borderline) | 5 | 맥락이 불충분한 표현. 정확도 계산에서 제외 |
| **합계** | **30** | 모두 합성 문장, 실제 계좌/URL/피해자 데이터 없음 |

**계산식**

- 위험 재현율(Recall, Sensitivity) = 위험 메시지 중 탐지한 건수 / 위험 메시지 15건
- 미탐지(False Negative, FN) = 위험 메시지인데 '명확한 신호 없음'인 건수
- 오경보율(False Positive Rate, FPR) = 정상 메시지인데 경고한 건수 / 정상 메시지 10건
- 경계 사례는 정답 확정이 어려우므로 별도 출력, 위 정확도 계산에서 제외

**주의:** 합성 예시 30건은 대표 표본이 아니며 **실제 국민 대상 탐지율, 피해예방률, 의료·금융적 신뢰성을 주장할 근거가 아니다.** 특정 패턴에 유리한 데이터일 수 있고 수치는 사례 구성에 민감하다. 실제 자료로 검증할 때는 개인정보법·동의·기관 협력 절차 필요.

## 05-3a. API 요청 본문 상한 보안 보완 (코드 작성, 실행 미검증)

**2026-10-30 원격 GitHub 파일 작성 사항:**
- `src/lib/request-guard.ts`: 8KiB(8,192바이트) 제한, JSON 형식 검사, `Content-Length` 확인, 본문 스트림 읽기 중 실제 누적 바이트 재확인, 잘못된 JSON 차단.
- `src/app/api/analyze/route.ts`: 무제한 `request.json()` 호출 대신 `readBoundedJson` 연결. 잘못된 본문은 일반화된 오류만 반환하며 요청 원문은 응답에 포함하지 않음.
- `tests/request-guard.test.ts`: 정상 JSON, 잘못된 JSON 400, 미지원 Content-Type 415, 크기 초과 413, 빈 요청 400 등 **5개 신규 테스트 코드 작성**.

**중요:** 이 검사는 **서버가 JSON을 파싱하기 전 앱 내부 처리량 상한**이며, 프록시/호스팅 인프라가 요청을 받는 과정의 메모리·트래픽 상한을 대체하지 않는다. `Content-Length`는 신뢰하지 않고 본문 스트림 누적 바이트도 확인한다. 실제 호스팅의 공격 내구성은 배포 환경에서 따로 검증해야 한다.

**현재 상태:** 코드 작성 및 GitHub 반영 완료. 사용자 WSL2에서 `npm run typecheck` → `npm test` → `npm run build` → API HTTP 400·413·415 동작 검증은 **PENDING**. **P0 요청 횟수 제한은 여전히 미구현**이며 공개 배포는 **BLOCKED**.

## 6. 용어

- **FNR (False Negative Rate, 미탐지율):** 위험 메시지인데 경고하지 못한 비율
- **FPR (False Positive Rate, 오경보율):** 정상 메시지인데 위험하다고 잘못 경고한 비율
- **P0 (Priority 0, 최우선):** 공개 배포 전 반드시 해결할 문제
- **정적 점검(Static Review):** 코드를 읽고 위험을 파악. 실제 보안 공격 검증은 별개
- **요청 제한(Rate Limiting):** 과도한 API 호출 방지
