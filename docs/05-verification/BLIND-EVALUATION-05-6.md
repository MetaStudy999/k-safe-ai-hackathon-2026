## 0. 왜 별도의 자료가 필요한가

기존 30건과 05-4의 24건에 맞춰 탐지 규칙을 개발했다. 개선 뒤 기존 30건·24건 모두 위험 재현율 100%, 정상 오경보율 0%를 기록했으나, **규칙 개발에 사용한 데이터의 반복 시험**이다. 이 수치를 독립 검증 또는 실제 금융사기 정확도로 표현하지 않는다.

**05-6에서는 규칙을 보지 않은 다른 작성자가 합성 메시지를 작성하고, 코드 수정 전에 정답표·파일 해시를 동결**한다.

## 1. 독립 제작·심사 원칙

1. **작성자 분리:** 개발 담당자가 아닌 다른 사람이 `src/lib/safety.ts`·기존 합성 사례 54건을 보지 않고 새로운 합성 문자 작성. 기존 문장 변형·검색엔진에서 복사한 실제 피해자 메시지 사용 금지.
2. **실제 개인정보 배제:** 실제 전화번호·계좌·주민번호·비밀번호·피해자의 원문·실제 악성 URL 금지. 모두 가상의 문장.
3. **사전 라벨 검토:** 작성자 2인 검토를 권장. `scam`은 금융사기 위험을 가정한 합성 시나리오, `benign`은 명백한 일반 문장, `borderline`은 판단 불확실 문장. 불일치는 `borderline`으로 분류하고 이유 기록.
4. **규칙 수정 금지:** 첫 실행 이전에 원본 데이터와 현재 코드 Git 커밋을 고정. 최초 결과를 저장하기 전 규칙/라벨/문장 수정 금지.
5. **최초 측정 보존:** 첫 평가의 TP, FN, FP, TN, 재현율, 오경보율, 실패 ID를 수정 없이 기록. 그 이후 개선용으로 활용한 문장은 더 이상 독립 자료가 아니다.

## 2. 합성 데이터 형식

프로젝트 밖 별도 로컬 파일로 작성한다. 파일명 예시: `$HOME/k-safe-eval-external.json`. **이 파일은 실제 연락처나 개인정보를 포함하지 않아야 하며, 별도의 보관·공유 동의를 얻기 전까지 Git에 등록하지 않는다.**

전체 24~200건. **위험 10건 이상, 정상 10건 이상, 경계 4건 이상**. JSON 최상위는 사례 배열:

```json
[
  {
    "id": "EX001",
    "expected": "scam",
    "category": "가상의 금융 위험 상황",
    "message": "별도 작성자가 만든 합성 위험 문장"
  },
  {
    "id": "EX002",
    "expected": "benign",
    "category": "정상적인 일상 상황",
    "message": "별도 작성자가 만든 합성 정상 문장"
  },
  {
    "id": "EX003",
    "expected": "borderline",
    "category": "확인이 필요한 상황",
    "message": "의도가 불분명한 합성 문장"
  }
]
```

위 세 행은 **형식 예시일 뿐 실제 평가 데이터가 아니다**.

## 3. 준비된 평가 명령 — 실제 데이터가 제공된 후에만 실행

```bash
cd /home/ubuntu/codyssey/k-safe-ai-hackathon-2026
export PATH="$HOME/.nvm/versions/node/v24.22.0/bin:$PATH"
git pull --ff-only origin main || exit 1
node --import tsx scripts/evaluate-blind.ts "$HOME/k-safe-eval-external.json"
```

- [평가 실행기](../../scripts/evaluate-blind.ts)는 JSON의 필수 필드·사례 수·중복·라벨과 기본 개인정보 형식 등을 검사.
- 결과에는 **평가 데이터 SHA-256**, TP/FN/FP/TN, 재현율·오경보율, 실패한 **ID·범주**만 표시하고 원문 메시지는 출력하지 않음.
- 원문 데이터가 외부 시스템으로 전송되도록 코딩하지 않았으며, 임의로 Git 커밋·푸시·배포하지 않음.
- 정규식 마스킹만으로 개인정보 없음이 보장되는 것은 아니므로 사람이 별도로 검토해야 함.

## 4. 품질 판정 방법

- 게이트 기준은 **실제 대회 요구사항과 사용 목적을 확인한 후** 확정한다. 현재 근거 없이 90%·95%를 '공식 기준'이라 주장하지 않는다.
- FN(위험 누락) 및 FP(정상 오경보)의 사례별 원인을 검토하되, 05-5와 마찬가지로 점수만 맞추기 위한 문자열 규칙 추가를 금지.
- 표본이 작아 단일 %의 불확실성이 크므로 표본수·혼동행렬·원본 해시를 함께 보고한다.
- 독립 합성 세트만으로도 실제 금융사기 탐지율·실사용 안전성이 보장되지 않으며, 개인정보 보호·호스팅 WAF·로그·LLM 조건은 별도 검증한다.
