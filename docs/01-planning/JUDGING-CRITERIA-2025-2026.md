## A. 공식 대회 심사자료 비교 (최근 2025~2026)

### A-1. 2025 제3회 KISIA 정보보호 개발자 해커톤

- **주최/주관:** 과학기술정보통신부 / 한국정보보호산업협회(KISIA)
- **대회 주제:** AI를 활용한 보안 서비스 개발
- **예선 평가:** 창의성 · 적합성 · 완성도
- **본선 평가:** 구현성 · 완성도 · 주제 적합성 · 현장 미션
- **본선 증빙:** 결과보고·발표·시연·제출코드 검증
- **동점 우선순위(본선):** 구현성 > 완성도 > 적합성 > 현장 미션
- **공개 운영요강의 항목별 수치 배점:** **미기재** (임의 추정하지 않음)
- **상격 참고:** 최우수상으로 과학기술정보통신부 장관상 명시
- **출처:** [주최·주관기관 작성 「2025 제3회 KISIA 정보보호 개발자 해커톤 운영요강」, 원본문서의 공개 사본(PDF)](https://media-cdn.linkareer.com/activity_manager/applications/582527) (문서 p.1, p.5 참조; 호스팅은 제3자 CDN)

**K-SAFE 시사점:** 설명만 하는 보안 챗봇이 아니라 실제로 작동하는 개인정보 마스킹·분석·안전행동 추천을 시연하고, 코드 검증에 대비한다.

### A-2. 2026 기상·기후 AI 해커톤

- **기관:** 기상청 기상기후인재개발원
- **서류심사 배점:** 주제 적합성 **20** · 체험/참여형 설계 **25** · 학습 효과 **10** · 독창성 **15** · 실현 가능성 **30** = **100점**
- **본선 운영:** 웹 기반 인터랙티브 도구를 URL 접속 후 실제 체험·시연. 위 수치가 본선 채점표와 동일하다고 단정하지 않음.
- **출처:** [2026 기상·기후 AI 해커톤 공식 홈페이지](https://weatherhackathon.kr/) (FAQ의 심사기준 및 대회 진행 일정 참고)

**K-SAFE 시사점:** 사용자가 직접 '송금 전/후/앱 설치 후'를 바꿔 보며 권고의 차이를 체험할 수 있는 화면이 중요하다.

### A-3. 2026 KW 해커톤 (광운대학교)

- **본선 배점:** 실현·상용화 가능성 **30** · 구현 완성도/기술력 **20** · 지역 문제 적합성 **20** · 창의성/차별성 **20** · 발표 **5** · 참여도 **5** = **100점**
- **발표:** 팀당 **5분 발표 및 질의응답**으로 안내
- **특이사항:** 지역사회 문제 해결 대회로, '지역 문제 적합성'을 K-SAFE 대회에 그대로 적용할 수는 없음
- **출처:** [2026 KW HACKATHON 공식 홈페이지](https://www.kw-hackathon.co.kr/) (본선 심사 기준)

**K-SAFE 시사점:** 발표와 디자인만으로 승부하지 말고, 작동성과 문제 적합성을 증명해야 한다.

### A-4. 2026 금융 AI Challenge (금융보안원)

- **주최:** 금융보안원 · **후원:** 금융위원회
- **주제/제출요건:** 금융 현안 해결 AI 아이디어 및 실제 작동하는 웹서비스. 공통 제출물은 **기획서 + 기능명세서 + 웹서비스 URL**, 발표 진출팀은 소스코드와 발표자료 제출
- **직접 연관 사례:** 보이스피싱 등 이상금융거래 탐지 시 *맞춤형 행동 요령*을 제공하는 AI 보안 비서가 대회 주제 예시로 제시됨
- **상세 수치 배점:** 확인한 공개 공식 안내에 **명시되어 있지 않음**
- **출처:** [금융보안원 「2026 금융 AI Challenge」 개최 안내](https://www.fsec.or.kr/bbs/detail?bbsNo=11997&menuNo=66) / [대회 운영 페이지](https://daker.ai/public/hackathons/2026-finance-ai-challenge)

**K-SAFE 시사점:** '피싱 탐지 + 맞춤 행동 요령'만으로 신규성 주장 불가. **왜 이 서비스가 다른가**를 별도 증거로 설명하고, **웹서비스 URL의 안정성**을 확인한다.

## C. K-SAFE 자체 제안 심사표 — 100점 (공식 아님)

**용도:** 현재 공식 심사기준이 없는 상태에서 개발 우선순위와 발표 증거를 관리하기 위한 내부 자가 평가. 아래 배점은 **K-SAFE 제안안**이다.

| 번호 | 내부 평가항목 | 배점 | 확인할 증빙 |
|---|---|---:|---|
| J-01 | 주제 적합성 | **20** | AI 추천 + 정보보호 흐름을 하나의 시연으로 확인 |
| J-02 | 창의성·차별성 | **20** | KISA 스미싱 확인 등 기존 서비스와의 차이: 사용자 상황별 조치·안내 |
| J-03 | 구현 완성도·실현성 | **20** | 공개 HTTPS URL, 처음부터 끝까지 작동하는 2~3분 사용자 흐름 |
| J-04 | AI 기술성·검증 | **15** | 위험 근거·불확실성 표시·합성 데이터 테스트·누락/오경보 |
| J-05 | 개인정보 보호·보안 | **10** | AI 전송 전 마스킹, 비밀키 미노출, 로그 최소화, 악성입력 대응 |
| J-06 | 국민 안전·사회적 효과 | **10** | 송금 전/후 대응 차이 및 공식 피해대응 경로 |
| J-07 | 발표·시연 | **5** | 발표자료, 시연, 장애 대체 경로, 질의응답 |
| | **합계** | **100** | |

### C-1. 점수 입력을 위한 간단한 기준

- **0%**: 해당 증거 없음
- **25%**: 설명/계획만 존재
- **50%**: 일부 구현 또는 일부 근거 확인
- **75%**: 작동하고 확인 가능하지만 미흡한 부분 존재
- **100%**: 실제 동작·근거·재현/검증이 모두 갖춰짐

**모든 항목의 점수는 실측 완료 전 '미평가(NOT_EVALUATED)'로 둔다.** 계획만으로 실제 달성 점수를 부여하지 않는다.

### C-2. 가산점 대신 필수 게이트(Gate)로 둘 안전 기준

아래 기준에 실패하면 합계 점수가 높더라도 **해커톤 제출준비 FAIL**로 판정한다.

- [ ] 사기 '안전함'을 확정 단언하지 않고 불확실성 고지
- [ ] 실제 주민등록번호·비밀번호·금융계좌·API 키가 저장소 및 AI 입력 로그에 포함되지 않음
- [ ] 이미 송금한 사용자에게 AI 응답 지연 없이 **112·금융회사 연락**을 우선 안내
- [ ] 테스트에 실제 피해자 개인정보가 아닌 합성 데이터를 사용
- [ ] 공개 URL에서 전체 시나리오가 작동하며 발표 중 재현 가능
- [ ] 제출 기한·형식·권리/AI 활용 규정 등 **실제 대회 공식 공고**를 확인

## E. 24시간 해커톤에서의 우선순위

1. **최우선:** 가상 메시지 입력 → 개인정보 가림 → 위험 근거 → 송금 전/후 상태별 조치 → 공식 경로 안내까지 작동
2. **그다음:** 실제 웹 배포, 합성 테스트·보안 테스트, 근거 있는 차별화 비교
3. **발표 대비:** 평가표에 맞춘 5분 이내 설명, 2~3분 라이브 시연과 오류 대비 정적 캡처/영상
4. **이번 범위 제외:** 실시간 통화 분석, 기관 시스템 직접 연결, 송금/지급정지 자동 실행

### 참고 문헌과 출처 관리 원칙

- 공식 홈페이지·주최기관이 작성한 운영요강을 우선한다.
- 2025 KISIA 원본문서는 주최/주관 작성 공고문이지만 파일 호스팅은 제3자 CDN이다.
- 참가하려는 해커톤의 공고가 확보되면 참고 대회보다 **해당 공고가 항상 우선**한다.
- 공고에 없는 배점·상격·자격·제출 규정을 추정해서 쓰지 않는다.
