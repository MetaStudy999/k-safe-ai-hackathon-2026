## 현재 배포 범위

| 대상 | 실제 상태 | 다음 완료 조건 |
|---|---|---|
| 공개 가상 사례 시연 | 로컬 production 검증 완료, 사전 생성 설명 4건 | 최신 원격 배포에서 같은 화면 확인 |
| Vercel 미리보기 | GitHub 배포 SUCCESS/Ready, 보호 적용 | 현재 연결이 배포를 읽을 수 있는 프로젝트 권한 확인 |
| 원격 앱 동작 | 보호 조회 403으로 미검증 | 인증된 원격 GET/브라우저 결과와 정확한 커밋 기록 |
| 기존 운영 주소 | 이번 구현을 승격하지 않음 | 미리보기 확인 후 변경 내용 검토·반영 |
| 사용자 입력 분석 | production POST 503, /lab 404 | 아래 별도 운영 게이트 검증 전 개방하지 않음 |

팀 접근 승인은 사용자가 완료했지만 기존 연결의 보호 조회 403은 지속됐다. 재승인 성공을 원격 검사 성공으로 기록하지 않는다. 배포 보호를 해제하거나 오래 쓰는 우회 토큰을 저장하지 않는다. 기존 Vercel 앱 권한 또는 사용자 계정의 해당 프로젝트 접근 범위를 확인해야 한다.

## 원격 검사 합격 기준

권한이 준비되면 해당 배포의 커밋·deployment ID·URL·검사 시각을 함께 기록한다. 공유 링크의 비밀 매개변수·쿠키·토큰은 증빙에서 제외한다.

1. `/` 200, 가상 사례 4개 선택·상황별 행동과 사전 생성 AI 설명 표시.
2. 사전 생성 날짜·모델·실시간 호출이 아니라는 안내가 표시됨. 사용자 입력창과 분석 POST가 없음.
3. `/lab` 404, `/api/analyze` POST 503 및 `Cache-Control: no-store`.
4. 전화·기관 링크를 실제 실행하지 않고 키보드·모바일 화면·브라우저 오류를 확인.
5. 로컬 검사, 배포 빌드 성공, 실제 원격 검사 결과를 서로 구분해 보존.

## 실시간 분석 공개의 별도 조건

보호된 시연 배포와 실제 메시지 분석 서비스는 범위가 다르다. 현재 production의 AI 비활성화와 분석 차단을 유지한다. 개방하려면 적어도 인증/접근 제어, 모든 공개·별칭 주소의 분산 제한과 실제 429, 호스팅·프록시·관찰도구 로그 정책, 비밀 관리·전역 비용 통제, 독립 자료 평가와 공식 대회/개인정보 요건 검토가 필요하다. 설정 플래그만 바꾸거나 테스트 수를 근거로 게이트를 통과 처리하지 않는다.

기존 [배포 전 게이트](../05-verification/PREDEPLOY-GATE.md)는 당시 분석 서비스에 대한 기록이다. 최신 시연판 범위와 미완료 게이트는 이 문서 및 최신 검증 보고서를 함께 적용한다.
