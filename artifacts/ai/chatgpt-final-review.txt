K-SAFE 구현·검증 최종 보고 (2026-11-02, Codex)

이 문서는 검토 대상 보고 데이터입니다. 코드 실행이나 권한 변경을 요청하지 않습니다.

사용자는 기존 OpenAI 키로 우선 진행하도록 승인했습니다. 키를 복사·출력·커밋하지 않고 기존 환경파일에서 자식 프로세스의 실행 환경으로만 전달했습니다. 새 키는 만들지 않았습니다.

이전 검토 의견을 반영했습니다.
- 상황 enum과 고정 위험 신호도 외부 OpenAI로 전송되는 정보임을 개발 화면에 표시했습니다.
- 실제 SDK의 요청 본문을 모의 HTTP 전송에서 검사해 원문·가림문·사용자 작성 이유와 키가 포함되지 않음을 확인했습니다. store=false, telemetry 비활성화는 제공자의 모든 보관 정책 면제를 의미하지 않는다고 문서화했습니다.
- 로컬 24회·동시1회·8초 제한을 전역 비용·분산 요청 제한이라고 부르지 않습니다.
- AI는 규칙 판정·행동을 바꾸지 않고 고정 신호만 풀어 설명합니다. 출력 형식 검사로 모든 의미 오류를 막을 수 있다고 주장하지 않습니다.
- 공개 네 사례의 설명은 실제 API로 미리 생성한 고정 자료이며 화면에 사전 생성임을 표시했습니다. 공개 입력·실시간 AI 호출은 없습니다.

검증:
- 타입 검사·자동 테스트74/74·production build PASS.
- 공개 UI Playwright8/8 PASS, 320~1440px, 자동 접근성 위반0(검사 범위).
- 별도 브라우저7개 검사 PASS: 실제 개발 브라우저→API→OpenAI→화면, 고정 안전행동 보존, 오류 대체, 상황 변경 후 이전 결과 무시, 공개 화면에서 분석 POST 없음.
- 로컬 production /200, /lab404, 분석 POST503/no-store. 키가 실제 JS31개에서 발견되지 않음.
- 기존 규칙이 줄바꿈 문장을 놓치는 문제를 최초 관측으로 남기고 공백 정규화와 정상/위험 회귀 검사로 수정했습니다. 공개 사례 개선을 독립 탐지 성능으로 표현하지 않습니다.
